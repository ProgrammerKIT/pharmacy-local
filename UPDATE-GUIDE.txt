藥局關係筆記 v1.5.0｜資料整理

沿用已設定的自動更新
1. 儲存 Mac 與 iPhone 正在編輯的內容，保持可連到 Mac。
2. 開啟原 App；Mac 更新器會檢查 GitHub，也可在 Mac 管理頁按「立即檢查更新」。
3. 等待安全切換，確認兩台「同步與備份」的本機 App 版本各自顯示 v1.5.0，再開始補登。
4. 從主選單開啟「資料整理」。手機主選單可左右滑動。
本次沿用原圖示、網址、憑證、配對與資料；不需要重新安裝或重新匯入既有 CSV。

資料整理怎麼用
- 疑似重複：查看比對理由，按「並排核對」。確認為不同分店可保存判斷；若確實相同，先保留兩筆，本版未提供完整門市合併。
- 缺漏與格式：選擇想檢查的欄位，按「補登欄位」。只顯示空白欄位，核對後儲存；已有值要修改時按「檢查門市資料」。
- 原始 CSV 有可辨識資料時可展開補值建議，核對檔名、行號與內容，再按「採用此值」。來源缺少或有歧義時自行確認，未知欄位可留空。
- 已確認不同：可撤回先前的核對。辨識資料變更時會重新出現在待核對清單；聯絡窗口的補登不會讓有效核對失效。
- 核對、補登及撤回均保留歷史，經同步才會出現在另一台裝置。

CSV 匯入檢查
1. 選檔後核對欄名對應、文字編碼與來源清單名稱。欄名有歧義時請指定；無對應的欄位仍保留在原檔。
2. 產生預覽，以待核對／無法匯入／缺漏提醒等篩選查看原檔行號。
3. 檢查門市比對線索，選擇新增、連結既有門市或略過。
4. 展開「門市欄位差異與可補值」，逐項勾選要補上的空白欄位。未勾選就保留原狀，已有資料的欄位不覆蓋。
5. 核對備註差異，按「確認並加密匯入」。未對應備註欄位不會改變舊備註；已對應但原列空白，保留舊文並標示來源缺少。
6. 同步成功後，另一台開啟並同步才會取得整理結果。資料於預覽後改變時，需重新產生預覽。
含匯入列的完整原始 CSV 會一併加密保存，因此原檔仍包含略過的列。

本次使用合成資料完成程式與事件流程測試；尚未在你的 Mac／iPhone 驗證本版畫面與實際更新。

連線診斷怎麼看
Mac 服務已回應／HTTPS 驗證通過：只代表本次請求已通過該裝置的 HTTPS 驗證並收到程式回應。
配對有效：Mac 接受此裝置的同步憑證；仍須實際同步才會更新客戶資料。
配對失效：從原 App 的「重新配對此裝置（保留本機資料）」修復，使用原資料庫密碼。
尚未確認：未收到足夠資訊，不會直接猜成防火牆或憑證故障。
若正在更新切換，先稍候再試；若持續無回應，檢查 Mac、區域網路與防火牆。

Norton 曾阻擋這個服務的處理方式
開啟 Norton：Security → Smart Firewall → Settings → Traffic Rules → Application rules。
找到 supervisor.mjs，核對是藥局程式的服務，設為綠色勾選「允許」。
清單不一定顯示 node。保留防火牆開啟，再從手機 App 檢查連線及同步。
這是允許該程式的應用程式規則，不代表已建立只限某個埠號的規則。
App 無法讀取 Norton 規則，因此不會自動宣稱所有失敗都是 Norton 引起。

這是唯讀檢查，不會修改 launchd、防火牆或背景執行權限。
若服務停止，管理網頁不能自行啟動它；從原安裝資料夾執行 05-Enable-Autostart.command。
若另有手動執行 02-Start 的視窗，先在該視窗按 Control+C，避免重複啟動。
若仍出現 Bootstrap failed，保留錯誤訊息供檢查，不要改用 root、不重跑 01-Setup。
本次沒有更換既有登入啟動工具或更新器；正常使用中的 Mac 無需重裝。

5. 工具在你的 Mac 產生程式發布私鑰，顯示對應公鑰指紋。它不是客戶資料庫密碼，也不能解密客戶資料。
6. 若同意 GitHub Actions 自動簽署程式，在工具確認問題輸入 YES；工具透過已登入的 gh，把這把程式私鑰存入該庫的 PHARMACY_SIGNING_KEY Secret。私鑰不會輸出到畫面或加入程式碼。
   不同意則不啟用線上更新。需要「簽章私鑰也永不上雲」時，應另改成在你 Mac 人工簽署發布的路線。
7. 從新資料夾執行 05-Enable-Autostart.command，重啟受管理服務並載入信任設定。若你本來手動執行 02-Start，先在那個 Terminal 按 Control+C。
8. GitHub 程式與 Secret 就緒後，在儲存庫 Actions → Signed program release → Run workflow（main）發布第一個版本。後續 main 提交或版本標籤會自動觸發；Pull request 只測試不發布。已有相同版本時不覆蓋。
9. 管理頁按「立即檢查更新」。相同版本會顯示沒有較新版；測試更高版號的簽署發布，才會實際觸發切換。

後續日常操作
你打開 App／回到前景且連得到 Mac 時，App 會請 Mac 檢查程式更新（同一分鐘的重複請求合併）。Mac 啟動時及每 24 小時也會檢查。
下載與驗證需要時間；不是每次開啟都能在第一秒看到新版本。離線、Mac 睡眠或更新暫停時繼續使用已安裝版本。
有新版：下載 → 簽章與檔案檢查 → 等待編輯完成 → 保存加密檢查點 → 試啟動 → 切換。手機下次連回 Mac，下載完整新版介面，沒有未儲存內容時自動重新載入。
打開多個分頁時，全部都要沒有未儲存內容；舊版無法回應安全確認時，先關閉該舊分頁。背景或離線手機不會永遠卡住 Mac 更新，回來仍可合併相容資料。
CSV 預覽若不打算匯入，按「取消本次匯入」清掉預覽，才會讓更新繼續；這不會刪掉已匯入的資料。
你不必每次重新配對、輸入密碼、下載 ZIP、替換資料夾或重新匯入 CSV。
我不會在對話結束後自行持續寫新版；必須實際完成新版程式並發布，這套流程才會傳遞更新。

失敗與退版
下載失敗／簽章不符：保留現行程式，顯示原因。
新版無法啟動或本機 HTTPS 健康檢查失敗：退回原程式，暫停更新，保留客戶資料現況。
切換途中斷電：下次啟動看到未完成交易，回到原版並暫停更新。
已啟動但功能有問題：管理頁按「退回上一版程式」。它只回復程式版本，不把客戶紀錄倒退成舊資料。
首次安裝 1.4 更新器以前的 1.3 不在這個自動退版管理範圍。舊資料夾仍保留，如需回到 1.3，先停止 1.4 服務，再由原資料夾啟動，勿同時啟動。
啟動檢查不是完整使用者功能驗收；無法自動知道所有介面或業務邏輯問題。

不要改的項目
不要刪除 Library/Application Support/PharmacyLocal-CS。
不要更改 Mac .local 名稱、埠號、瀏覽器或隨意撤銷配對。
不要公開 tls、config.json、snapshot.json、updates 的加密檢查點、發布私鑰或客戶資料包。
不要把同步一致當成獨立備份；另做加密離線外接備份並確認可還原。

發布者操作摘要
純程式匯出：node scripts/release.mjs --code-only /一個全新本機資料夾
簽署包：由 GitHub workflow 設定 GITHUB_REPOSITORY、PHARMACY_RELEASE_SEQUENCE、PHARMACY_SIGNING_KEY 執行 node scripts/release.mjs。
新版本必須同時更新 package.json、public/version.js、public/sw.js 的版本及介面標示，通過全部測試，再提交 main 或推送對應 vX.Y.Z 標籤。沒有簽章 Secret 時只執行測試，不產生 Release。
版本與已見發布序號都必須增加。同一版本不覆蓋原 Release；修正問題請發布新 patch 版本。
只有 bootstrap 1／protocol 1／schema 2 的相容更新允許自動安裝。更新器本體、根信任、Node 或資料格式遷移仍需人工升級。
