# 藥局關係筆記 v1.5.51 · 實際拜訪距今天數

## v1.5.51 實際拜訪距今天數

- 實際拜訪日期右側統一顯示「距離目前 N 天」；當天明示「距離目前 0 天」。附近／最近使用門市、門市清單與單店畫面共用此顯示。
- 沿用台北曆日計算，窄畫面自然換行；尚未確認日期與未來日期保留原提示。只調整顯示文字，未改動正式資料、日期計算、儲存或同步流程。

## v1.5.50 隱藏零待辦提示

沒有未完成任務時，不顯示「下次記得：待辦 0 項」與「目前沒有未完成任務」。已完成歷史仍可展開查看／再加入待辦，其他門市提醒與修改入口保留。拜訪卡片、單店頁、完整門市編輯及提醒彈窗共用此顯示方式；只調整畫面，不刪除任務或修改資料。SOP1 1.2.37、資料格式與同步規則不變。

## v1.5.49 實際拜訪日期與距今天數

儲存門市提醒、待辦完成／再加入、門市資料或拜訪筆記時，新增「當下是否為拜訪日期」確認，每次預設不勾選。勾選後按確認儲存，內容與本次實際拜訪確認一起保存；未勾只保存一般修改，不更新最近實際拜訪。文字修改的前後差異核對仍保留。

- 附近／最近使用門市、門市清單、單店畫面顯示最近實際拜訪與距今天數。單店可展開拜訪日歷史，查看每次明確確認的時間與來源版本。
- 日期採台北曆日，同一天多次確認合併顯示為一個拜訪日；舊筆記日期不改，不以匯入或編輯時間補猜過去拜訪。沒有確認過就顯示「尚無已確認的拜訪日期」。
- 返回修改／Escape／切到背景不提交正式變更；未勾選且提醒或行內文字沒變時不新增版本。純內容不變但勾選時，只保存新的實際拜訪確認來源。
- 確認保留在原 revision，普通修改、衝突處理、還原、CSV 與同步不會複製成新拜訪。加密同步及備份原樣保留，匯入預覽另外列出新增確認及拜訪日數。門市合併／搬移不改寫歷史歸屬。
- App v1.5.49／SOP1 1.2.37，schema 2、同步 protocol、21 個 runtime 路徑與 CSV 引擎 1.2.16 不變。Mac 與 iPhone 都更新後才可在兩端操作新確認。真 iPhone 驗收仍須在實機執行。


## v1.5.48 表單輸入避開鍵盤

- 保留開啟頁面與表單時不自動叫出鍵盤的規則；使用者主動點選輸入後，門市提醒及一般文字欄位也納入可見位置調整，避免輸入處落在鍵盤後方。
- 鍵盤高度或可視區位移改變時，只做讓輸入位置可見所需的最小捲動，不把表單拉回頂端。手機彈窗標頭採緊縮排版，增加可用輸入空間，並尊重手動捲動與文字選取。
- 調整只涉及顯示與捲動，不重寫文字或變更選取，不觸發正式儲存；既有本機加密草稿、修改差異與最後確認保留。沒有資料結構轉換，不修改原文、門市、CSV、Source Snapshot、備份或同步資料。
- App v1.5.48／SOP1 1.2.36，CSV 匯入引擎仍為 1.2.16，runtime 維持相同 21 個路徑。真 iPhone／Typeless 尚待實際裝置驗收，不以瀏覽器模擬冒充已通過。

## v1.5.47 鍵盤按需開啟

- App 各頁面、門市提醒、新增／完整編輯及單店拜訪，開啟時先供閱讀，不自動聚焦文字欄位。恢復草稿或從修改前後對比返回，也不強制叫出鍵盤；使用者直接點文字欄位後再輸入，桌面 Tab 導覽仍可正常使用。
- 勾選自訂提醒、清除搜尋與切換頁面不再強制進入文字輸入；關閉對話框或從背景回來時，不恢復文字輸入焦點。輸入欄位仍可直接編輯，不用 `inputmode="none"` 或額外唯讀限制來封鎖鍵盤。
- App 與管理頁保留必填、最短長度等驗證；不合格時顯示錯誤並定位欄位，不自動聚焦輸入。修復配對改用 App 內配對碼表單，開啟／取消不連線，最後確認才沿既有同庫檢查、配對保存與同步流程執行；升級無須重新配對。
- 離開欄位或收起鍵盤不代表正式提交；本機加密草稿、修改前後比較、最後明確確認及版本衝突保護維持原流程。不改寫既有原文、門市、CSV 或 Source Snapshot，不增加正式資料版本或外部連線。
- Runtime 維持 21 個檔案，SOP1 1.2.35；CSV 匯入引擎仍為 1.2.16。瀏覽器焦點與手機尺寸測試不等於真 iPhone／Typeless 鍵盤驗收，實際裝置結果須另行記錄。

## v1.5.46 單店拜訪原文搜尋

- 在「單店拜訪」直接搜尋這間門市全部目前有效、無衝突的正式拜訪原文；逐字比對、英文不分大小寫，不展開同義詞。搜尋不包含提醒、下次跟進或舊版本，最多保留前 500 處命中；另有結果時明確提示縮小關鍵字。
- 顯示命中處數、目前位置、原始日期、來源與原文片段，可用上一處／下一處跳到原文。支援的瀏覽器以 Range 高亮原文；不支援高亮 API 時仍提供紀錄外框、片段與定位，不替換可編輯文字節點或移動選取游標。
- 中文組字期間暫停搜尋；原文輸入時暫停標示，已有文字或拜訪草稿時暫停搜尋及跳轉。完成或取消修改後，同一門市保留查詢並重算結果；修改仍先看前後差異、最後確認才保存。
- 查詢與結果只留在當次記憶體，換店、關閉、背景或鎖定即清空。搜尋不建立摘要、主題、提醒或資料版本，不改寫拜訪原文、CSV 或 Source Snapshot，不呼叫外部服務，不進入備份或同步。
- Runtime 維持原有 21 個檔案，SOP1 1.2.34；CSV 匯入引擎版本不變。程式測試及瀏覽器尺寸模擬與真 iPhone／Typeless 驗收分開記錄，不以模擬結果冒充真機結果。

## v1.5.45 備份影響預覽與確認

- 選取加密備份只在本機解密、驗證與預覽，不直接寫入。列出新增實體與版本、附件／原始來源、衝突、回收桶與逐筆內容差異；勾選已核對實際影響並按確認後才套用。
- 同庫採版本聯集，保留所有原文與歷史；較新修改／刪除可能改變目前狀態，多 head 不自動選邊。相同或舊備份沒有新增內容時無需套用，不新增寫入或待同步數量。
- 空白裝置還原在 IndexedDB 單交易保存成功後才採用新資料庫及金鑰；原裝置憑證不還原、不自動配對。過期預覽、未完成草稿、異庫、損毀來源、其他視窗競爭或儲存失敗都不報成功。
- 附件與 CSV 原始來源逐檔核實 SHA256；Source Snapshot、版本鏈及任務完成歷史沿用嚴格驗證。讀取預覽與取消不建立任何版本，也不呼叫外部服務。套用摘要保存在本機加密裝置狀態，不寫入共享 bundle。
- 備份不含未完成草稿、配對憑證或 GPS；匯出時間僅表示產生下載。可選檔確認可讀後取消，但這不等於已驗證外接碟或完成真機還原演練。
- 隔離瀏覽器驗收程式與真機驗收表見 [DEVICE-ACCEPTANCE.md](DEVICE-ACCEPTANCE.md)。真 iPhone／Typeless 結果須另行記錄，不以 Chrome 手機尺寸模擬冒充。Runtime 固定白名單不變，SOP1 1.2.33。

## v1.5.5 原始 CSV Source Snapshot

- 每次確認提交 CSV 時，每一份原始檔都先建立 append-only Source Snapshot，完整 bytes 以 SHA-256 為鍵加密保存；後續門市合併、人工裁定、文字整理與關聯圖不得回寫來源快照。
- 即使整份 CSV 的資料列最後全數略過或排除，原始檔仍會保存。相同 bytes 可共用同一 blob，但每次確認提交仍保留一次來源事件。
- 被納入門市／拜訪的來源列仍保存原始 headers、cells、實體行號與 row fingerprint，並指回本次 Source Snapshot。
- 「匯入 CSV」頁可查看最近保存的 Source Snapshot 並下載原始 CSV；下載前仍提示明文檔案風險。
- 相同 CSV 重傳不新增客戶門市或拜訪版本，但會留下新的 Source Snapshot 事件；新 CSV 版本與舊 CSV 版本並存。
- Source Snapshot record 不允許建立修改版本或刪除版本。現有資料 schema 維持 2；舊資料可直接讀取，但 Mac 與 iPhone 必須先更新到 v1.5.5，再提交新的 Source Snapshot。
- 資料庫總容量仍為 24 MB；達上限時整批提交失敗，不會自動刪除舊來源。詳細不變條件見 `SOURCE-SNAPSHOT.md`。

## 接通此儲存庫的自動更新

發布來源：`ProgrammerKIT/pharmacy-local`。

1. 在自己的 Mac 安裝 GitHub CLI，執行 `gh auth login`，用瀏覽器登入自己的 GitHub 帳號。
2. 從目前已安裝的 PharmacyLocal 資料夾執行 `08-Configure-Updates.command`，輸入 `ProgrammerKIT/pharmacy-local`。
3. 工具在你的 Mac 建立程式簽章金鑰。確認後，程式簽章私鑰存入此儲存庫的 `PHARMACY_SIGNING_KEY` Actions Secret；客戶資料庫密碼不會上傳。
4. 關閉 App 編輯畫面，從目前已安裝的同一資料夾執行 `05-Enable-Autostart.command`，讓服務載入更新來源。
5. 初次設定 Secret 後，到 Actions → Signed program release → Run workflow（main）執行一次。先查看 test 工作通過，再確認 Releases 出現正式版本及 PharmacyLocal.pharmaupdate。
6. Mac 管理頁按「立即檢查更新」。若目前已是同版本，不會重裝；較新且相容的版本才會切換。iPhone 連回 Mac 後取得新版介面。

後續 main 有提交或版本標籤時，GitHub 會自動執行測試；新版本通過測試且已設定簽章 Secret 才發布。Pull request 只測試，不發布。沒有 Secret 時只顯示等待設定，不會發布未簽章程式。已存在的版本不覆蓋，修改執行程式前須增加版號。

GitHub 程式測試通過不代表你的 Mac 已設定完成；仍需在你的 Mac／iPhone 實測第一次更新。程式簽章只確認發布來源與檔案完整性，不能保證新版沒有缺陷。

## 保留的功能

本機 AES-256-GCM 加密、裝置自動開啟、區網加密同步、CSV 預覽匯入、同一來源備註的版本歷史、備註缺失時保留舊文、衝突確認、回收桶、關聯探索及加密備份均保留。不會重新建立客戶資料庫。

同一 Google 備註變更後，是「一筆備註內有 A、B 歷史版本」，不是主列表多出兩筆。來源比對依據門市識別與來源清單，不宣稱能取得 Google 沒有匯出的欄位 ID。不能確認時要求人工核對；App 手動文字不由 Google 新匯出直接覆蓋。

關聯圖仍沿用現有標記與字詞證據邏輯，不是自動本機 AI。相同姓名只是一條待確認線索，不代表已證實是同一人或兩家店有高度關係。這次沒有改寫既有關聯節點或原始客戶內容。

## 空間分工

- 程式：自己的 Applications/PharmacyLocal-v1.4.3，runtime/releases 保存後續版本。
- 客戶密文、配對設定、TLS：自己的 Library/Application Support/PharmacyLocal-CS，沿用舊版位置。
- 更新信任／狀態／升級前加密檢查點：上述資料目錄的 updates。
- 發布私鑰：自己的 Library/Application Support/PharmacyLocal-Publisher，不在程式儲存庫內。
- 手機及 Mac 瀏覽器：原 HTTPS 網址的 IndexedDB；保留密文與不可匯出的裝置 CryptoKey。不要換 .local 名稱、埠號或清除網站資料。
- GitHub：只有程式、合成測試及發布產物；Actions Secret 只放程式簽章私鑰，不放客戶資料庫密碼。

「程式更新」與「客戶資料同步」不同。手機必須能連回 Mac 才能拿到 Mac 的新版介面；在外面離線或不同網路，不會神奇地同步到家裡。第一次 v1.3 → v1.4 仍須完整關閉兩台的舊 App／相關分頁再重開。
