# 藥局關係筆記 v1.5.23 · 安全衝突合併預覽

## v1.5.23 安全衝突合併預覽

- 衝突版本若來自唯一共同版本，且各裝置只修改不同的一般欄位，核對頁會提出唯讀的安全合併預覽，逐項說明每個欄位取自哪一個版本。
- 同一欄位出現不同修改，或涉及刪除、附件、CSV／Source Snapshot、門市身分裁定、人物身分連結及 Google 來源狀態時，不提供自動合併建議，仍交由人工比較或整合。
- 預覽不寫入；只有在完整結果頁再次確認後才建立一個解決版本。核對期間若收到新版本會阻擋提交，原版本與來源歷史繼續保留。SOP1 1.2.11。

## v1.5.22 同步健康狀態

- 「同步與備份」新增同步健康卡，集中顯示本機保存、Mac 確認、待同步資料數量、待核對衝突與失敗狀態。
- 待同步數量依資料實體去重；同一筆拜訪連續修改仍只算一項，並分類為拜訪、門市、人物、主題或來源快照。
- 同步失敗不清除計數；只有 Mac 明確確認後才歸零。舊版已有待同步變更時不猜測數字，第一次成功同步後建立精確基準。SOP1 1.2.10。

## v1.5.21 唯讀拜訪重點卡

- 在拜訪紀錄及客戶門市卡片提供「拜訪重點卡」，集中顯示明確填寫的下次跟進、可追溯的原文候選提示與最近 3 筆拜訪原文。
- 卡片只在畫面開啟時計算，不生成摘要、不建立資料版本，也不改寫門市、拜訪、人物、主題、CSV 或 Source Snapshot。
- 衝突、回收桶與身分待確認資料不會混入卡片；沒有日期的紀錄維持「原始日期未提供」。SOP1 1.2.9。

iPhone PWA ＋ Mac 本機 HTTPS 服務。這個公開儲存庫只保存程式，不提供線上客戶資料庫，也不使用 GitHub Pages。先閱讀 UPDATE-GUIDE.txt。已接通 v1.4 自動更新來源的裝置，沿用原 App 即可取得相容更新；尚未安裝更新器才使用 07-Upgrade-v1.4.command。

本交付包是純程式，不附客戶 CSV、加密客戶資料包、客戶備份、裝置憑證或發布私鑰。它會沿用你的 Mac 已有資料與資料格式，新增可選的門市核對紀錄。不能直接雙擊 public/index.html 當成 App 使用。

## v1.5.20 座標補查預覽

- 首頁可載入私人座標補查 JSON，依目前門市清單顯示可更新與略過項目、舊新網址與座標。僅預覽不寫入。
- 名稱、地址、地點識別或版本有疑點即略過，不按同名配對，不進行身分裁定。重複載入不重寫既有座標。
- 確認後只新增地圖網址版本，保留人工欄位、CSV、Source Snapshot 與舊版本；沿用加密同步。預覽過期阻擋整批提交。
- SOP1 1.2.8，schema 2 與更新檔案白名單不變；純程式包不含私人補查結果。安裝更新不會自動套用座標。

## v1.5.19 手機附近門市

- 手機開啟並解鎖 App 後，自動請求一次目前位置；取得許可後，首頁列出有可靠座標的最近 3 間既有門市及約略直線距離。點選仍可開始拜訪。
- 電腦同位置顯示最近使用的 3 間門市，不請求定位。手機定位拒絕、逾時或無座標時顯示明確原因，並以最近使用門市作備用。
- 僅解析既有 Google Maps 連結中的明確座標，不把地點識別碼或地圖視角中心當作門市座標，不對外查店。不足 3 間就顯示實際可計算筆數；畫面揭露座標涵蓋率與遺漏較近門市的可能。
- GPS 只留在當次記憶體，鎖定、切背景及切換資料庫時清除，不寫入紀錄、備份或同步。作業系統定位服務自身可能使用網路。
- SOP1 1.2.7，資料 schema 2 不變。若既有門市只有地點 ID，本版不能單憑 ID 找出最近門市，需另行取得可靠座標。

- 核對期間有新版本會阻擋提交；未完成草稿不得被採用版本流程覆蓋。原版本、附件歷史與 Source Snapshot 保留。
- SOP1 1.2.6；runtime schema 2 與原更新檔案白名單不變。本次不操作任何正式客戶資料。

## v1.5.7 Source Snapshot 顯示刷新

- 修正「匯入 CSV」頁在 App 尚未解鎖資料庫時先渲染，之後即使資料已解鎖或同步完成，仍可能停留在「已保存原始 CSV · 0 份」的顯示問題。
- 進入「匯入 CSV」頁、解鎖後重新渲染、成功取得新版資料或合併備份後，只要目前沒有未完成的 CSV 預覽，就會重新從當下加密 bundle 計算 Source Snapshot 數量與最近清單。
- 若正在進行 CSV 預覽／裁定核對，刷新不會清掉使用中的檔案或預覽。
- 這是顯示生命週期修正：不新增、刪除、重建或改寫任何 Source Snapshot，也不改資料 schema、SOP1 裁定或既有門市整併結果。

## v1.5.6 已裁定既有門市整併

- 已核對資料包若帶有精確的 `identityRule: same`，而 App 現況同時存在多筆符合「同一 Google 地點識別＋核准名稱＋地址範圍」的既有門市，預覽可建立一次性的既有門市整併計畫。沒有這項明確裁定時仍不得自動合併。
- 保留門市必須能由裁定的顯示名稱唯一決定。候選超出裁定範圍、門市或拜訪有同步衝突、人工「確認為不同門市」紀錄、既有身分裁定矛盾、非空白門市欄位互相衝突，或同一來源清單在兩筆門市各有拜訪版本時，整批阻擋，不以檔案順序猜測。
- 安全整併時，被整併門市建立刪除版本並記錄 `mergedInto` 與裁定鍵；既有拜訪建立新版本改連到保留門市。附件、舊版本、原始 CSV 來源、清單、別名與裁定歷史都保留。
- 預覽會先顯示「哪些既有門市 → 哪一筆保留門市」以及將搬移多少筆既有拜訪。這類已裁定整併不能用下拉選單改指其他門市來繞過；要改變去向必須取消本批並重新裁定。
- 正式提交仍先保存本批每一份原始 CSV Source Snapshot。整併、來源對齊、備註版本更新與 Source Snapshot 在同一次本機加密提交中完成；任一安全檢查失敗則整批不寫入。
- 回收桶會標示「已整併」門市；若人工還原，App 會警告該門市將重新成為獨立門市，之後必須重新核對身分。
- SOP1 升級至 1.0.3；runtime schema 維持 2。建議 Mac 與 iPhone 都先更新至 v1.5.6，再使用會觸發既有門市整併的已核對資料包。

## v1.5.5 原始 CSV Source Snapshot

- 每次確認提交 CSV 時，每一份原始檔都先建立 append-only Source Snapshot，完整 bytes 以 SHA-256 為鍵加密保存；後續門市合併、人工裁定、文字整理與關聯圖不得回寫來源快照。
- 即使整份 CSV 的資料列最後全數略過或排除，原始檔仍會保存。相同 bytes 可共用同一 blob，但每次確認提交仍保留一次來源事件。
- 被納入門市／拜訪的來源列仍保存原始 headers、cells、實體行號與 row fingerprint，並指回本次 Source Snapshot。
- 「匯入 CSV」頁可查看最近保存的 Source Snapshot 並下載原始 CSV；下載前仍提示明文檔案風險。
- 相同 CSV 重傳不新增客戶門市或拜訪版本，但會留下新的 Source Snapshot 事件；新 CSV 版本與舊 CSV 版本並存。
- Source Snapshot record 不允許建立修改版本或刪除版本。現有資料 schema 維持 2；舊資料可直接讀取，但 Mac 與 iPhone 必須先更新到 v1.5.5，再提交新的 Source Snapshot。
- 資料庫總容量仍為 24 MB；達上限時整批提交失敗，不會自動刪除舊來源。詳細不變條件見 `SOURCE-SNAPSHOT.md`。

## v1.5.4 門市身分裁定沿用

- SOP1 升級至 1.0.1。首次出現且沒有命中既有裁定的門市身分疑點，仍須在匯入或合併前由使用者確認。
- 已確認為同一間門市的規則會保存外部 Google 地點識別、允許的原始名稱、確認地址與裁定來源；後續只有證據完全符合時才自動沿用。
- 新名稱、不同地點識別、地址矛盾、人工拆分／合併或同步衝突都會停止自動沿用，重新列入核對；別名遇到新地點識別不會靜默建立第二間門市。
- Google 識別只作可變更的外部證據；App 本機門市 ID 才是永久主身分。裁定只限精確門市，不擴張到整個品牌或其他分店。
- 裁定資料仍保留各 CSV 的原始名稱、網址、清單、行號、原文與來源。維持 bootstrap 1／protocol 1／schema 2，既有裝置可用原自動更新流程取得此版。

## v1.5.3 原始店名通路篩選

- 「客戶門市」與「關聯探索」的門市清單加入通路按鈕。可複選通路，並搭配文字、地區和門市型態篩選；兩頁共用本次開啟的條件。
- 同時選多個通路會列出其中任一通路的門市，再與其他條件取交集。「全部通路」只清除通路選取；「清除篩選」重設全部條件。數字是套用文字、地區及型態後的門市筆數。
- 優先讀取保留的 CSV 原始店名。沒有原始名稱時才使用保存的來源別名或目前門市名稱。顯示名稱和原始文字保持原樣；備註提及其他藥局不會改變通路。
- 依使用者裁定，「佑全」與「健康人生」同屬「佑全／健康人生」。其他選項依原始店名的明確品牌前綴；這是名稱分群，不代表已驗證企業隸屬。不同分店仍是不同門市。
- 多個來源指向不同通路時標示「通路待確認」，無法辨認者保留「未分群」。不把未分群推定為獨立藥局，也不擴大尚未確認的別名關係。原始來源仍可在門市卡片查閱。
- 篩選只改變清單顯示，不寫入門市、拜訪、關聯、來源或同步資料。不產生通路關係節點；原有身分待確認的關聯圖限制保持有效。鎖定或切換重建資料庫時會清除篩選。
- 沿用現有資料與自動更新，維持 bootstrap 1／protocol 1／schema 2 及原 21 個 runtime 檔案，不需要清空或重新匯入 CSV。更新後從原 App 的「客戶門市」點選通路即可使用。

## v1.5.2 全部資料重建與備份隔離

- Mac 管理頁加入「清空全部資料並重建」：先保存現有加密資料到 `archives`，再一次切換為全新空白資料庫；清除作用中門市、手動備註、拜訪、附件、人物、主題、歷史及關係。
- 舊裝置配對立即失效；正在傳送的舊請求也不能寫入新庫。重啟服務後隔離仍有效。更新程式本身不會自動清空資料。
- 每台裝置的「同步與備份 → 改用重建後的資料庫」先把本機舊資料封存，再切換到 Mac 新庫。封存與切換使用同一筆本機交易，失敗時保留原狀；多視窗的舊寫入會被拒絕。
- 舊備份不在作用中的資料庫內，不參與同步、重複偵測、CSV 匯入或關聯分析。Mac 管理頁可匯出本次重建前備份；App 可查看並匯出本機隔離備份。舊庫備份不能合併到新庫。
- 密碼在瀏覽器內產生新加密資料，服務不接收密碼。新庫密碼需離線保存；隔離備份仍使用原庫密碼。

操作順序：兩台先更新至 v1.5.2 → Mac 管理頁重建一次 → 為每台產生不同的一次性配對碼 → 原 App 各自改用新庫 → Mac 載入已核對資料包並確認匯入 → iPhone 同步。重建只執行一次；未來一般 CSV 更新沿用 SOP1 預覽，不必再次清空。離線或未切換的裝置仍可能顯示其舊資料，必須在該裝置完成切換。

## v1.5.1 SOP1 匯入前整理

- 每次 CSV 匯入遵循 `SOP1.md`：原檔與逐欄文字保存、門市候選核對、來源新版與 App 手動文字比較，通過後才確認加密寫入。
- 「載入已核對資料包」承接使用者已核對的門市分組、暫用顯示名稱、排除列與待確認標記。相同 Google 地點 ID 不會推翻分開的裁定。
- 所有比對在本機進行。按「匯出核對結果（明文）」可取得本批與相關 App 紀錄的比較報告；載入或匯出預覽都不寫入資料庫。
- 保留待確認的門市與原文，暫不列入關聯圖；核實後在門市編輯頁明確解除標記。同一份裁定資料包重傳不增加重複紀錄，也不重設已核實的身分。
- 保護 App 人工備註與缺少來源版本的舊文字；同一來源多個版本或同步衝突先核對。不同來源的相同全文整合顯示，原文仍各自保存。
- 維持 bootstrap 1／protocol 1／schema 2 與原 21 個 runtime 檔案。兩台裝置都更新到 v1.5.1，再備份並使用裁定資料包；尚未實測使用者的 Mac／iPhone。

使用入口：原 App →「匯入 CSV」→「載入已核對資料包」→ 匯出核對結果 → 處理疑點 → 確認並加密匯入。此版本仍不提供既有門市完整合併。

## v1.5.0 資料整理

- 主選單新增「資料整理」：疑似重複、缺漏與格式、已確認不同三份清單。
- 比對名稱、地址與可辨識的 Google Maps 地點連結，列出理由與不同分店的線索。比對時處理空白、全半形、大小寫與臺／台差異，原始資料保持原樣。一般地圖搜尋網址不作為同一地點的證據。
- 並排核對後可記錄「確認為不同門市」，也可撤回。核對紀錄會加密保存、保留歷史並同步；辨識資料改變後重新核對。本版不提供完整門市合併。
- 缺漏依地址、縣市、地區、通路、拜訪窗口與地圖網址篩選。只補上由你確認的空白欄位；已有欄位透過原編輯功能修改。未知欄位可以留空。
- 原始 CSV 中可辨識的欄名提供補值建議，附檔名與行號；來源有不同值會列出選項。建議必須人工核對，不會查詢外部服務或推測聯絡資料。
- CSV 增加拜訪窗口對應、空白／重複／歧義欄名檢查、欄位長度與格式提示、同批及既有門市比對。預覽支援待核對、錯誤、提醒、選取列篩選，展示備註新舊差異與門市欄位差異。
- CSV 連結既有門市時，可逐項勾選補空白欄位；原本非空白的值保留。互相矛盾的補值、未處理的衝突或已過期預覽會阻止整批寫入。
- 未對應備註欄位時，既有備註與來源缺失狀態不變。相同列出現在不同來源清單時，分別保留來源與備註版本。完整原檔、原文、手動修改與既有歷史沿用原保存機制。
- 相容 bootstrap 1／protocol 1／schema 2；簽章更新仍替換原本 21 個 runtime 檔案，沿用原網址、圖示、配對與自動更新設定。建議兩台更新到 v1.5.0 再開始補登。

使用入口：開啟原 App →「資料整理」，或「匯入 CSV」→ 產生預覽 → 核對 → 確認並加密匯入。

目前比對採明確規則，不能保證找出所有重複門市。待核對配對先顯示最多 200 組，超出時會提示繼續核對；已保存的有效核對紀錄仍可查看及撤回。現有每批 1,500 列、10 檔、單檔 2 MB／合計 5 MB 與資料庫 24 MB 上限維持不變。

驗證方式與真機測試限制見 TEST-RESULTS.txt。

## v1.4.4 穩定性修正

- 本機 App 程式版本、最近確認的 Mac 程式版本與本機已確認的資料版本分開顯示。
- 最近成功同步時間沿用加密保存結果；沒有新變更仍更新時間。另列本次開啟期間最近的同步失敗時間與原因，恢復後仍可看到該次失敗紀錄。
- 「檢查連線」只讀取版本端點，不讀寫客戶快照、不刷新成功同步時間。HTTP 401 可確認已到達 Mac 服務與本次 HTTPS 驗證通過，但配對失效；未收到可辨識回應時無法區分防火牆、TLS、DNS 或網路問題。

## 接通此儲存庫的自動更新

發布來源：`ProgrammerKIT/pharmacy-local`。

1. 在自己的 Mac 安裝 GitHub CLI，執行 `gh auth login`，用瀏覽器登入自己的 GitHub 帳號。
2. 從目前已安裝的 PharmacyLocal 資料夾執行 `08-Configure-Updates.command`，輸入 `ProgrammerKIT/pharmacy-local`。
3. 工具在你的 Mac 建立程式簽章金鑰。確認後，程式簽章私鑰存入此儲存庫的 `PHARMACY_SIGNING_KEY` Actions Secret；客戶資料庫密碼不會上傳。
4. 關閉 App 編輯畫面，從目前已安裝的同一資料夾執行 `05-Enable-Autostart.command`，讓服務載入更新來源。
5. 初次設定 Secret 後，到 Actions → Signed program release → Run workflow（main）執行一次。先查看 test 工作通過，再確認 Releases 出現正式版本及 PharmacyLocal.pharmaupdate。
6. Mac 管理頁按「立即檢查更新」。若目前已是同版本，不會重裝；較新且相容的版本才會切換。iPhone 連回 Mac 後取得新版介面。

後續 main 有提交或版本標籤時，GitHub 會自動執行測試；新版本通過測試且已設定簽章 Secret 才發布。Pull request 只測試，不發布。沒有 Secret 時只顯示等待設定，不會發布未簽章程式。已存在的版本不覆蓋，修改執行程式前須增加版號。

GitHub 程式測試通過不代表你的 Mac 已設定完成；仍需在你的 Mac／iPhone 實測第一次更新。程式簽章只確認發布來源與檔案完整性，不能保證新版沒有缺陷。

## 保留的功能

本機 AES-256-GCM 加密、裝置自動開啟、區網加密同步、CSV 預覽匯入、同一來源備註的版本歷史、備註缺失時保留舊文、衝突確認、回收桶、關聯探索及加密備份均保留。不會重新建立客戶資料庫。

同一 Google 備註變更後，是「一筆備註內有 A、B 歷史版本」，不是主列表多出兩筆。來源比對依據門市識別與來源清單，不宣稱能取得 Google 沒有匯出的欄位 ID。不能確認時要求人工核對；App 手動文字不由 Google 新匯出直接覆蓋。

關聯圖仍沿用現有標記與字詞證據邏輯，不是自動本機 AI。相同姓名只是一條待確認線索，不代表已證實是同一人或兩家店有高度關係。這次沒有改寫既有關聯節點或原始客戶內容。

## 空間分工

- 程式：自己的 Applications/PharmacyLocal-v1.4.3，runtime/releases 保存後續版本。
- 客戶密文、配對設定、TLS：自己的 Library/Application Support/PharmacyLocal-CS，沿用舊版位置。
- 更新信任／狀態／升級前加密檢查點：上述資料目錄的 updates。
- 發布私鑰：自己的 Library/Application Support/PharmacyLocal-Publisher，不在程式儲存庫內。
- 手機及 Mac 瀏覽器：原 HTTPS 網址的 IndexedDB；保留密文與不可匯出的裝置 CryptoKey。不要換 .local 名稱、埠號或清除網站資料。
- GitHub：只有程式、合成測試及發布產物；Actions Secret 只放程式簽章私鑰，不放客戶資料庫密碼。

「程式更新」與「客戶資料同步」不同。手機必須能連回 Mac 才能拿到 Mac 的新版介面；在外面離線或不同網路，不會神奇地同步到家裡。第一次 v1.3 → v1.4 仍須完整關閉兩台的舊 App／相關分頁再重開。
